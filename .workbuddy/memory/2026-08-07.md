## 高帧率 CI 真红修复（链接期 undefined symbol）
- 用户点 Re-run 后 CI 真跑起来了，报**链接错**（非 infra）：`Undefined symbols for architecture arm64e/arm64: _DYYYApplyFPSOverlaySettingChange / _DYYYApplyHighFPSSettingChange`，来自 `DYYYSettings.xm.o` 的 `__showDYYYSettingsVC_block_invoke_7`。
- **根因**：跨文件的 C 函数声明被**内联写在 `DYYYSettings.xm` 方法块内**（`extern void DYYYApply...`），而 Makefile 强制 C++（`CXXFLAGS += -std=c++11`），`.xm` 按 C++ 编译 → 名字修饰（mangling）不一致：引用侧生成 C 风格 `_DYYYApply...`，定义侧（DYYYHighFPS.xm）生成 C++ mangled 名，链接器对不上。
- **修复（照搬仓库既定范式）**：新建 `DYYYHighFPS.h`，用 `extern "C" { ... }` 包裹两函数声明（与 `DYYYFloatSpeedButton.h` 完全一致）；`DYYYHighFPS.xm`、`DYYYSettings.xm` 顶部 `#import "DYYYHighFPS.h"`；删掉 `DYYYSettings.xm` 内联 `extern`。这样定义侧因 import 同头文件也走 C 链接，名字一致，链路闭合。
- **铁律（写入避坑）**：本仓库任何跨 .xm/.m 文件共享的全局 C 函数，**一律写进 `.h` 头文件 + `extern "C"` 包裹 + 两边 `#import`**；绝不可在方法体内写块级 `extern`。否则 C++ 编译单元下必现 mangling 链接错。
- 提交 `75f2e54`（DYYYHighFPS.h 新增 + DYYYHighFPS.xm/DYYYSettings.xm 改），已 push（7075216..75f2e54）。
