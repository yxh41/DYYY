# 2026-08-29

## 修复：滑进对方主页「有几率闪退」（作品日期功能 EXC_BAD_ACCESS）

### 现象
- 用户报「滑进对方主页的时候，有几率闪退」，附两段 Cr4shed/CrashReporter 日志（`文本(35).txt` / `文本1.txt`）。
- 两段日志同源：`EXC_BAD_ACCESS (SIGSEGV)`，`objc_retain` 访问非法地址 `0x20`（=32，小整数被当对象指针），主线程 `-[UIView(CALayerDelegate) layoutSublayersOfLayer:]` → `UICollectionViewAnimation`，元凶 `DYYY.dylib`。iOS 16.4.1 / AwemeLite 40.1.0。

### 定位方法（离线符号化）
- 本机无 `nm`/`atos`/`objdump`，用 Python 手写 Mach-O 解析器定位：
  1. 读 fat 头（`0xcafebabe`），拆 arm64e 切片（offset 1409024）。
  2. 解析 `LC_FUNCTION_STARTS`（ULEB128 编码的函数起始表）→ 得到崩溃偏移所属函数边界。
  3. 手写 AArch64 反汇编器（只解 BL/ADRP），把崩溃偏移映射到源码函数。
- 崩溃偏移 `0x3d9ec` 落在函数 `0x3d984`（= `DYYYNumberValue`），其上一条指令 `BL objc_retainAutoreleasedReturnValue` 之前是 `performSelector:` 调用。
- 调用链确认：`layoutSubviews` → `DYYYUpdatePostDateLabelForCellCore`(0x3cd6c) → `DYYYExtractTimeRecursive`(0x3db5c) → `DYYYExtractTimeRecursive2`(0x3e768) → `DYYYNumberValue`(0x3d984) 崩溃。

### 根因
- `DYYYNumberValue` / `DYYYAwemeModelFromProfileCell` 里用 `[obj performSelector:NSSelectorFromString(key)]` 读**返回类型未知**的动态字段。
- `performSelector:` 返回 `id`，遇到返回标量（如 `NSTimeInterval`/`double`/`NSInteger`）的 getter，会把标量当指针返回，ARC 随后 `objc_retainAutoreleasedReturnValue` 对该野指针 retain → 信号级崩溃（`@try@catch` 抓不住）。
- 「有几率」因为只有反射遍历到返回标量的字段（如 `createTimeInterval` 这类 NSTimeInterval）才崩。

### 修复（commit 见下，DYYY.xm −15/+22）
- `DYYYNumberValue`：删掉 `respondsToSelector:` + `performSelector:` 路径，只走 `valueForKey:`（自动把标量包装成 NSNumber，安全且覆盖更全）。
- `DYYYAwemeModelFromProfileCell`：同样删掉 `performSelector:` 路径，只走 `valueForKey:`；并跳过 NSNumber/NSString/NSValue 结果（避免把标量包装物误当 model 缓存）。
- 其余 `performSelector:` 调用（1562/1669/3861/4448/5316/10119/10134/10599）都是写死 `@selector(对象类型方法)`，相对安全，未动。
